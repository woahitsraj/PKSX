# Use Cloudflare and Better Auth for Cloud Sync

PKSX's first Sync Provider is a PKSX-operated service using Cloudflare Workers for authenticated access, SQLite-backed Durable Objects for revision and publication metadata and TinyBase transport, private R2 for raw artifacts, and Better Auth with D1 for identity and sessions. We choose this existing TinyBase transport and control over coherent publication while accepting responsibility for operating passwordless authentication, maintaining the service, and integrating email delivery. Managed Supabase would reduce authentication operation but require more revision-transport adaptation; its higher advertised starting fee is not evidence that Cloudflare has a lower total cost.

The provider-neutral coordinator retains causal authority and the accepted adapter contract. The [research and trade-off review](../research/cloud-sync-provider-contract-fit.md) identifies the publication, cleanup, revocation, deletion, and native sign-in behavior that implementation must still prove. Accepted by the user on 2026-11-14 for [Select the Cloud Sync provider](https://github.com/woahitsraj/PKSX/issues/414); this selects no email vendor, quota, paid plan, or budget and does not authorize purchases, account changes, or infrastructure implementation.
