# Derive platform floors from one browser baseline

PKSX supports a single browser baseline across every surface, Safari 26, Chromium 140, and Firefox 151, and derives its native deployment floors from that baseline rather than inheriting them from Capacitor's project templates, giving `IPHONEOS_DEPLOYMENT_TARGET = 26.0` and `minSdkVersion = 29`. The baseline is a fixed version set rather than a rolling policy, so a locked layout spec can cite it and raising it stays a deliberate decision. This extends ADR 0007: the web surface is the origin and native targets follow it.

The floors this replaces were never chosen. `@capacitor/ios@8.4.2` declares `s.ios.deployment_target = '15.0'` and `@capacitor/android@8.4.2` falls back to `minSdkVersion 24`, and both values entered the repo verbatim when the platforms were scaffolded. The app never worked on them, because `100dvh` requires Safari 15.4 and Tailwind v4 emits media query range syntax requiring Safari 16.4. Chromium 140 is chosen for `env()` safe-area behavior rather than for CSS features, which are far older, and Firefox 151 is where container style queries ship. iOS WebKit is tied to the OS, so an iOS 26 device always meets the baseline, but Android WebView updates independently, so `minSdkVersion 29` makes Chromium 140 reachable without guaranteeing it and safe-area fallbacks stay necessary. Devices below the baseline, meaning iPhone XS and older, macOS before Sonoma, Android before 10, and Firefox before 151, degrade gracefully and are not supported.
